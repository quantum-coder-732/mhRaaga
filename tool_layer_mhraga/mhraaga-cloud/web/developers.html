Architecture

Tiers. music engine raga grammar, composer, physics, GAN, auto-tune (music_engine_framework_layer/mhraaga_engine) · cloud api/ Lambda, web/ site, infra/ CloudFormation · app mhraaga-app Flutter · factory offline agents that fill the catalogue; they use one function (Shapley credit split) from the separate Kalkee orchestrator. The live site does not run Kalkee.

Everything is served from one domain. The browser never talks to another origin (a strict CSP: no inline scripts or styles, connect-src 'self'). The Lambda is reachable only through CloudFront, which adds a secret header; the raw API Gateway address returns 403.

How a song is made

  1. Brief: a language model (OpenRouter) turns the prompt into raga, tala, tempo, mood, language, lead and lyrics. If it fails, keyword rules still produce a song.
  2. Raga: 30 classical ragas, the 72 melakartas, or a gopi raga from 1 to 16000.
  3. Score: compose.py writes alap, gat and tihai (landing exactly on sam). Then the physics (Box2D) adds rubato, note weight, meend glide and drift; the GAN offers phrases; auto-tune pulls pitch back to the shruti.
  4. Sound: the score is plain JSON, rendered on the device by synth.js or synth.dart.
  5. Voice: each lyric line is spoken by a neural voice model, cached in S3 and shared by everyone, then mixed over the music with ducking.

Sound

The instruments are physical models, not samples: Karplus-Strong plucked strings for tanpura and veena, a breathy bansuri, a reed harmonium with body resonance, tabla by its modes, a room reverb, tape-style saturation, human timing and phrase dynamics. Details and measurements: docs/SOUND.md in the repository.

API for external developers

Read this first. There are no API keys: you create an account and send its token. Each account has a quota of 30 songs a day. Call the API from a server or app, not from another website's JavaScript: no CORS headers are sent, so browsers on other domains are blocked. Base URL: https://www.mhraaga.in/api. Throttled to about 20 requests a second; sign-in 2 a second; 8 wrong passwords lock an account for 10 minutes.
B=https://www.mhraaga.in/api
TOKEN=$(curl -s $B/auth/login -H 'Content-Type: application/json' \
   -d '{"email":"me@example.com","password":"..."}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

curl -s $B/compose -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
   -d '{"prompt":"a calm morning bhajan to Krishna","language":"hindi","duration":120}' > song.json

Score format

{ "sa": 233, "duration": 238.4, "lead_voice": "bansuri",
  "drone":  {"sa": 233, "second": 349.5, "low_sa": 116.5, "pluck": 1.5},
  "lead":   [[t, hz, dur, ornament, velocity, glide], ...],   // ornament 0 none, 1 meend, 2 kan
  "tabla":  [[t, "Dha", "both", 1.0], ...],                    // class: left, right, both
  "lyrics": [{"t": 40.1, "dur": 3.2, "text": "...", "tag": ""}],
  "sections": [{"name": "alap", "t0": 0, "t1": 37.9}, {"name": "gat", ...}, {"name": "tihai", ...}],
  "meta": {"raga": "Bhairavi", "tala": "keherwa", "tempo": 76, "physics": {...}} }

It is plain JSON, so you can render it with your own engine, export MIDI, or use web/synth.js and mhraaga-app/lib/synth.dart as references.

Secrets (OpenRouter key, JWT secret, origin secret) live in SSM Parameter Store, never in the repository.

Limits, stated plainly

  • The instruments are models, not recordings: far less electronic than before, but not a live band.
  • The voice speaks the words; it does not sing them to the tune. Indic pronunciation is good but not perfect.
  • Composing and speech call paid hosted models, so they are capped per user per day and per site per day.
  • There is no API key system or CORS yet. If you need either, deploy your own copy or open an issue.
