What "live-verified" actually means here

Not a guess — real HTTP calls against the live production deployment, this session, with logged results:

  • Real conversation-memory round trip ("remember the number 42" → "you asked me to remember the number 42" in a follow-up call).
  • Real Auto Hybrid pick for CodingAgent (ok: true against production).
  • Real GLM/Hy4/Gemini/Luna provider visibility check via GET /api/chat/providers.
  • Real latency measurements (13.8s cold / 0.2-5.4s warm for ollama-coder; 161ms → 9ms for the auth cache).
  • Real nightly-PEFT pipeline run through GGUF conversion, quantization, Ollama tag creation, sanity check, and the regression gate — the gate correctly refused to promote a worse candidate.

What's NOT yet verified, and why

  • The 105-prompt SLM test suite (scripts/run_slm_test_suite.py) has not been run for real — needs the deploy server (unreachable this session after a point). Ready to run the moment it's back: docker exec ak-chatbot python -m scripts.run_slm_test_suite --provider ollama-coder.
  • 5 of 9 agents (openclaw-agent, mcp-utility-agent, langchain-research-agent, code-security-agent, supply-chain-agent, cloud-config-agent) were not touched by any change this session and were not re-exercised live — their status here is "automated tests pass," not "confirmed working against production this session." No code in this session's diff affects them, so there's no specific reason to suspect a regression, but that is an inference from "nothing changed nearby," not a live check.
  • The auto-approval bar UI (Pause/Approve/Reject/Stop) compiles clean and is wired end-to-end, but wasn't click-tested in a real VS Code window this session (no GUI access from this environment) — see the demo runbook artifact from earlier in this session for the "verify once yourself" flag on this specific feature.
  • Mobile app: code changes verified via flutter analyze (clean) and a release APK builds successfully, but wasn't run on a real device/emulator this session.

Recommendation

Before treating this as fully verified end-to-end: reconnect to the deploy server, run the 105-prompt suite for real, and do one real click-through of the VS Code approval bar and one real mobile app session. Everything else in this table already has a real, specific, checkable basis for its status — this section exists so "all agents verified" isn't overstated for the parts that weren't actually re-checked this session.
