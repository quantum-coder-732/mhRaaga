Studio features and what was not integrated

Built into the site and API: spoken poems, stories / pravachan / explainers (1 to 30 minutes, written section by section by the model, narrated by the device's voices over a raga bed), People (consent, voice samples, speaking-style notes learned from pasted transcripts), AI rules in S3 (rules/ethics.json, editable by an administrator, versioned in rules/history/), and the self-learning loop (rules/learned.json feeds default tāla, tempo and instrument per language). The Android app has songs, poems and speech; stories, People and Studio are web-only for now.

Not copied into this project, on purpose: - VoiceStudio (debpalash/voicestudio) is AGPL-3.0 and needs local GPU models. Embedding it in a hosted service would put this whole service under AGPL. Run it separately on your own machine with the exported samples. - Explainroo, VUZA and agnes-video-generator (MIT) are local Python/Node pipelines that render video with local models and ffmpeg. They do not run in Lambda. The site's Explainer produces the script and on-screen points and plays them; making an exported MP4 needs one of these on a machine with ffmpeg and a speech model. VUZA's Pinterest scraping is a terms-of-service risk and was not used. - YouTube links: the site does not download or transcribe videos. Paste a transcript (Show transcript) into a person's profile and it learns the style from that text. Links you add are kept as notes only. - Voice cloning and cloned-voice songs or videos: the browser and phone cannot do it, and nothing here clones a voice. Samples are stored (privately, with consent) for a local cloning tool. - Exported video / MP3 of narration: the browser cannot record its own speech voices, so narrated stories are played, not downloaded.

Film studio (effects editor)

film.html / film.js, shown in the one page. AI "Auto-direct": your idea → a director's brief → a storyboard (two model calls, rule-checked) → editable scenes. Per scene: caption, narration, duration, colours or an image, effects (glow, vignette, film grain, soft focus, light leak, slow zoom, fade, black and white, warm, cool, physics petals), colour grade (exposure, contrast, saturation, hue) and a brightness scope. Films are saved per user (create, open, edit, delete). Playback and export run in the browser; export is WebM with the picture and the raga music.

How the listed projects were used: | Project | Licence | What was done | |---|---|---| | Box2D (erincatto) | MIT | The physics petals use planck.js, the JavaScript port of Box2D by Erin Catto and Ali Shakiba (MIT, web/planck.mjs, licence in web/planck.LICENSE.txt). It is not applied to song audio or to the Kalkee Python layer. | | ba-click-fx | MIT | Idea only: the click ripple on the preview. No code copied. | | openrv-web | MIT | Idea only: colour grade controls and a brightness scope. No code copied. | | forge-film | MIT | Idea only: a storyboard as scenes. Scenes are rendered from effects, not generated by video models. | | effectcraft | Apache-2.0 | Reference for the effect set. It is a native Rust tool, so it was not embedded. | | awesome-cg-vfx-pipeline, HitFilm guide | none stated | Reading lists, not code. | | VisionDepth3D | none stated | Needs local depth models on a GPU; not used. |

Limits: there is no video generation (no AI-made footage), no timeline for separate video and audio tracks, and no cut-by-frame editing. The narration voice is the device's speech and is not in the exported file.
